# Dota 2 Draft + Mid Matchup Trainer

You are building this app end to end. Follow the phases in order, run it after each phase, and fix errors before moving on. If a requirement is ambiguous or an API field doesn't match this spec, inspect the real response, adapt, and note it in `NOTES.md`. Ask the user only when blocked.

## Purpose

Personal tool for ONE player. Two jobs:
1. **Draft helper:** pick own hero pool, input enemy picks, get suggested heroes (from the pool only) + item priorities.
2. **Mid matchup trainer:** drill every mid lane matchup until memorized (flashcards, quiz, spaced repetition, personal notes).

Scope is draft + itemization ONLY. No game mechanics content.

## Stack

- Next.js (App Router) + TypeScript + Tailwind. No database, no auth.
- User state (hero pool, notes, SRS progress) in `localStorage`, behind a single `lib/storage.ts` wrapper (easy to swap later). Include export/import JSON buttons.
- Data = static JSON generated by scripts into `/data`, committed. App reads JSON only; it never calls external APIs at runtime.
- Node scripts in `/scripts` (tsx). `npm run data:update` refreshes everything.

## Data sources

| Need | Source |
|---|---|
| Hero/item names, images, stats, components | `https://raw.githubusercontent.com/odota/dotaconstants/master/build/heroes.json`, `items.json` (and ability files if needed) |
| Overall win rates per hero per rank bracket | OpenDota `GET https://api.opendota.com/api/heroStats` |
| Hero vs hero matchups | OpenDota `GET /api/heroes/{id}/matchups` -> `[{hero_id, games_played, wins}]` |
| Item popularity by phase | OpenDota `GET /api/heroes/{id}/itemPopularity` |
| Win rate by game length | OpenDota `GET /api/heroes/{id}/durations` |
| Position-specific matchups/synergy (optional) | Stratz GraphQL, token in `.env` as `STRATZ_TOKEN`. Skip gracefully if missing. |

Rules: throttle OpenDota to ~1 req/sec, retry with backoff on 429, cache raw responses in `/data/raw`. Verify each endpoint's real shape before coding against it. Hero images: build URL from the `img` field in dotaconstants prefixed with `https://cdn.cloudflare.steamstatic.com`.

## Generated files

- `data/heroes.json`: id, name, localized_name, img, primary_attr, attack_type, roles
- `data/matchups.json`: `matchups[heroId][enemyId] = { games, wins, adjWr, delta }`
- `data/hero-stats.json`: overall wr, pick rate, per bracket
- `data/durations.json`: per hero, wr per duration bucket + derived `earlyScore`/`lateScore`
- `data/item-popularity.json`: per hero, items by phase
- `data/traits.json`: hero trait tags (see below)
- `data/item-rules.json`: counter-item rules (see below)
- `data/mid-notes.seed.json`: seed for mid matchup notes (empty-ish, user fills)

### Statistics rules

- Smoothing: `adjWr = (wins + K * heroOverallWr) / (games + K)` with `K = 50`.
- `delta = adjWr - heroOverallWr` (positive = hero does well into that enemy beyond its general strength).
- Ignore pairs with `games < 30` (show "low data").
- Default rank bracket: Divine+ if available, else all; make the bracket a dropdown stored in settings.

## Trait tags (`data/traits.json`)

Per hero: `tags: string[]`, `dmgType: "physical" | "magical" | "pure" | "mixed"`, `lanePlan`.

Allowed tags: `hard_cc`, `aoe_disable`, `silence`, `break`, `evasion`, `illusions`, `invis`, `heal`, `sustain`, `ranged_harass`, `burst_magic`, `phys_carry`, `blink_initiator`, `save`, `dispel`, `passive_heavy`, `summons`, `global`, `push`, `smoke_gank`, `mid_waveclear`, `mid_roamer`, `mid_tempo`, `mid_late_scaler`.

Bootstrap with a script that guesses from dotaconstants ability data (disable/silence/dispel flags, damage type), then write an editable `traits.overrides.json` that wins over the guesses. Include a `/admin/traits` page (dev only) to edit tags per hero and export JSON.

## Item rules (`data/item-rules.json`)

Declarative, evaluated against the enemy team's aggregated traits:

```json
[
  { "id": "bkb-cc", "if": { "countTag": { "hard_cc": ">=2" } }, "item": "black_king_bar", "tier": "rush", "reason": "{n} hard CC heroes" },
  { "id": "bkb-magic", "if": { "magicShare": ">=0.6" }, "item": "black_king_bar", "tier": "rush", "reason": "mostly magic burst" },
  { "id": "hood", "if": { "magicShare": ">=0.5" }, "item": "hood_of_defiance", "tier": "core", "reason": "magic damage heavy" },
  { "id": "mkb", "if": { "hasTag": "evasion", "heroDmg": "physical" }, "item": "monkey_king_bar", "tier": "mid", "reason": "evasion on enemy" },
  { "id": "sentries", "if": { "hasTag": "invis" }, "item": "gem_of_true_sight", "tier": "situational", "reason": "invis heroes" },
  { "id": "linkens", "if": { "countTag": { "hard_cc": ">=1" }, "heroRole": "core" }, "item": "sphere", "tier": "situational", "reason": "single target lockdown" },
  { "id": "ghost", "if": { "physShare": ">=0.7" }, "item": "ghost", "tier": "situational", "reason": "mostly physical damage" }
]
```

Seed at least 30 rules covering: BKB, Linken's, Lotus, Eul's, Ghost, Blade Mail, Hood, Pipe, Crimson Guard, Shiva's, Mekansm/Guardian Greaves, Glimmer, Force Staff, Silver Edge, Nullifier, Orchid, MKB, Heaven's Halberd, Aeon Disk, Satanic. Use real item internal names from `items.json`; validate them at build time and fail loudly on unknown names.

Item output for a hero = `item-popularity` baseline build, with rule hits merged in and re-ordered by tier (`rush` > `core` > `mid` > `situational`), each with a one-line reason.

## Features

### 1. Hero pool (`/pool`)
- Searchable grid of all heroes, click to toggle. Optional comfort level 1-3 per hero.
- Filter by attribute, role. Persist in storage.
- Separate "Mid pool" subset (heroes the user plays mid).

### 2. Draft helper (`/draft`)
- Pick up to 5 enemy heroes (search + grid). Optional position assignment per enemy.
- Mode toggle: **Lane** | **Teamfight** | **Macro** | **Balanced** (changes weights).
- Candidates are ONLY heroes in the user's pool.
- Scoring:
  - `lane` = mean `delta` vs the enemy heroes likely in the same lane (from assigned positions; if none, vs all enemies), plus trait-based lane rules.
  - `fight` = mean `delta` vs all 5 enemies + trait bonuses (e.g. has dispel vs silence-heavy enemy, has save vs initiators).
  - `macro` = duration fit: compare candidate `earlyScore/lateScore` against what the enemy team peaks at.
  - `final = wLane*lane + wFight*fight + wMacro*macro`. Weights per mode in `lib/scoring.ts` constants.
- Output: top 5 with score breakdown bars, and a generated "why" line from the biggest 2-3 contributors (e.g. "+4.1% vs Storm Spirit, has dispel vs their silences").
- Lane analysis panel: for each enemy lane duo/trio, show tags + plain-language summary (harass, sustain, kill potential, tower-dive threat).

### 3. Item priority (`/draft/[heroId]` or side panel)
- After choosing a suggested hero, show item list grouped by tier with reasons, plus the baseline build timeline.

### 4. Mid matchup trainer (`/mid`) — the main learning feature
- **Matchup table:** rows = mid heroes the user cares about (default: all heroes with mid role + user's mid pool), columns = enemy mid. Cell shows `delta` color-coded and games count. Click a cell to open the **matchup page**.
- **Matchup page** `/mid/[myHero]/[enemyHero]`:
  - Stats (delta, games, adjWr), trait-derived lane summary.
  - Auto "lane plan" skeleton from traits (who out-harasses, who has better waveclear, who wins level 6, rune control), clearly marked as generated.
  - **User notes** (markdown textarea, autosaved): what to skip/take, rune plan, key items, the one mistake to avoid. Seeded from `mid-notes.seed.json`.
  - Item priority for this matchup.
  - Button: "Add to drill".
- **Drill mode** `/mid/drill`:
  - Flashcards: front = "You are X vs enemy mid Y", back = user's notes + generated plan + items.
  - Quiz types: (a) "Enemy mid is Y. Which of your mid heroes is best?" (answer from data + user's pool), (b) "What's the first big item vs Y?" (answer from rules), (c) "Pick the correct lane plan" (from user notes).
  - Spaced repetition: Leitner boxes 1-5 with intervals 0/1/3/7/21 days. Wrong answer -> back to box 1. Track per-matchup box and next due date in storage.
  - Dashboard: due today count, matchups memorized (box >= 4), weakest matchups, streak.
- **Post-game log:** after a game, quick form (my hero, enemy mid, won/lost, what went wrong, tag). Wrong-tagged matchups are pushed back to box 1.

### 5. Settings (`/settings`)
- Rank bracket, export/import all user data, "refresh data" instructions (shows data timestamp and patch).

## UI

- Dark theme, dense, keyboard friendly (search focus with `/`, number keys to answer quizzes).
- Hero tiles use images; always show localized names.
- Mobile usable but desktop first.
- No loading spinners for data (it's static JSON).

## Phases and acceptance criteria

1. **Foundation:** scaffold, constants fetch, `heroes.json`, hero grid component, `/pool` working with persistence. Done when pool survives refresh.
2. **Data pipeline:** scripts for matchups, hero stats, durations, item popularity with throttle + cache. Done when `npm run data:update` produces all JSON and `matchups.json` has an entry for every hero pair with `games >= 30` flagged.
3. **Scoring + `/draft`:** implement smoothing, scoring with all 4 modes, unit tests for `lib/scoring.ts` (delta math, smoothing, mode weights, pool filtering).
4. **Traits + item rules:** bootstrap traits, rules engine with tests (each seeded rule has at least one test), item panel.
5. **Mid trainer:** matchup table, matchup page with notes, drill mode, SRS logic with tests (box transitions, due dates).
6. **Polish:** export/import, post-game log, keyboard shortcuts, README with run instructions.

## Non-goals

No accounts, no server DB, no live match tracking, no mechanics/guide content, no scraping of sites without an API.

## Deliverables

Working app (`npm run dev`), `npm run data:update`, `npm test`, `README.md`, `NOTES.md` listing any API deviations and assumptions.
